## 1. Setup

The test suite uses the [tasty](https://hackage.haskell.org/package/tasty) framework, with [tasty-hunit](https://hackage.haskell.org/package/tasty-hunit) for unit tests and [tasty-quickcheck](https://hackage.haskell.org/package/tasty-quickcheck) for property tests. All three are resolved through the Stackage snapshot already pinned in this project's 'stack.yaml' (`lts/24/55.yaml`, GHC 9.10.3 — see '00_agents.md'); as of the neighbouring LTS 24.56 snapshot that resolves to `tasty-1.5.4`, `tasty-hunit-0.10.2`, and `tasty-quickcheck-0.11.1` — confirm the exact pin with `stack ls dependencies` when the dependencies are added, rather than hard-coding a version here.

The test executable is declared in 'package.yaml' as:

```yaml
tests:
  genc3-test:
    main:                Spec.hs
    source-dirs:         test
    ghc-options:
    - -threaded
    - -rtsopts
    - -with-rtsopts=-N
    dependencies:
    - genc3
    - tasty
    - tasty-quickcheck
    - tasty-hunit
```

## 2. Test suite structure

The root 'test/Spec.hs' imports every test module qualified, and aggregates them into one `T.TestTree`:

```haskell
import qualified Test.Tasty as T

import qualified SpecParser -- test module for module Parser

main :: IO ()
main =
    T.defaultMain tests

tests :: T.TestTree
tests =
    T.testGroup
        "Tests"
        [
            SpecParser.testGroup
        ]
```

Each test module is named `Spec<Module>.hs` — e.g. 'src/Parser.hs' is tested by 'test/SpecParser.hs' — and exports a single `testGroup :: T.TestTree`:

```haskell
module SpecParser
    (
        testGroup
    ) where

import qualified Test.Tasty as T
import qualified Test.Tasty.QuickCheck as QC
import qualified Test.Tasty.HUnit as HU

import qualified Parser as P

-- ...

testGroup :: T.TestTree
testGroup =
    T.testGroup
        "module Parser"
        [
            tgUnitxParser
        ]
```

## 3. Test group and case naming

- A test group for an individual function is named `tgUnit<functionName>`; a test group for a type class law is named `tgLaw<LawName>`; a test group covering a whole type class is named `tgClass<ClassName>`.
- A `tgClass<ClassName>` group lists its law groups first, then the class's own unit-test groups.
- Within a group, an `HU.testCase` name ends with `"#u"` plus a number, incrementing per group (`"#u1"`, `"#u2"`, ...); a `QC.testProperty` name ends with `"#p"` plus a number, incrementing per group (`"#p1"`, `"#p2"`, ...).

## 4. Writing tests

An `HU.testCase` asserts a concrete input/output pair with `HU.@?=`:

```haskell
tgUnitxParser :: T.TestTree
tgUnitxParser =
    T.testGroup
        "xParser"
        [
            HU.testCase "#u1" (P.xParser "abc" HU.@?= "abc_tst"),
            HU.testCase "#u2" (P.xParser ""    HU.@?= "_tst")
        ]
```

A `QC.testProperty` states a property over arbitrary input, optionally guarded by a precondition with `QC.==>`:

```haskell
QC.testProperty "#p1" (\s -> length s < 100 QC.==> length (P.xParser s) == length s + 4)
```

## 5. Controlling QuickCheck sample distribution

The `Arbitrary` class controls how random test data is generated and how it is distributed. The standard types (`Bool`, `Char`, `Double`, `Float`, `Int`, `Integer`, `Word`, and so on) already have `Arbitrary` instances with a reasonable default distribution.

Where a test needs a non-default distribution over one of these existing types, a `newtype` wrapper is defined instead of overriding the type's own instance — the standard instance stays available, unmodified, for every other test:

```haskell
newtype PrintableAscii = PrintableAscii Char
    deriving Show

fromPrintableAscii :: PrintableAscii -> Char
fromPrintableAscii (PrintableAscii ch) = ch

instance QC.Arbitrary PrintableAscii where
    arbitrary =
        PrintableAscii <$> QC.frequency
            [
                (1, QC.elements ['A'..'Z']),
                (1, QC.elements ['a'..'z']),
                (1, QC.elements ['0'..'9']),
                (5, QC.chooseAny)
            ]
```

For a genuinely new type, its own `Arbitrary` instance is written directly, using `QC.frequency` to weight value ranges and `QC.choose` to sample within a range:

```haskell
instance QC.Arbitrary ParseState where
    arbitrary = ParseState <$> f <*> f <*> f
        where
            f = QC.frequency
                [
                    (1, QC.choose (minBound, -1)),   -- negative
                    (5, QC.choose (0, 3)),            -- common small values
                    (1, QC.choose (4, maxBound))       -- large values
                ]
```

## 6. Validation checklist

Before a function, law, type class, or module is considered tested, its test group carries a Haddock-style comment recording which of the following criteria are met, using `✅` (met), `❌` (not yet met), `❓` (unclear), or `N/A` (not applicable):

- **Function or law** — completeness (every equivalence class, or a representative random sample, is covered), independence (from other test methods), edge cases (covered via `HU.testCase`), and conformance to the function's documented contract (§5 of '02_04_coding.md').
- **Type class** — everything above, plus: every law and characteristic is documented with its prefix and a short description, every combination of instance types is tested, and a stub instance exercises every default-implemented function.
- **Module** — everything above for each of its exports, plus: the module header is fully documented (§3.1 of '02_04_coding.md'), and every exported class and function is reachable from the module's own `testGroup`.

```haskell
{-  * validated     : ✅
    * completeness  : ✅
    * independence  : ✅
    * edge cases    : ✅
    * conforms to doc: ✅ -}
tgUnitxParser :: T.TestTree
tgUnitxParser =
    T.testGroup
        "xParser"
        [
            -- ...
        ]
```
