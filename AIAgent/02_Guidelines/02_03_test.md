# Test guideline

This guideline defines the conventions for *product*'s automated test suite (folder 'test', output of phase 5 *Implementation and Test* — see '01_01_management.md' § Dependency order), in addition to the general rules of '01_01_management.md' (§ Document rules). It is tailored to *product* being built in C++ with the STL and Qt (see '00_agents.md').

## Terms

| Term | Context | Definition |
| --- | --- | --- |
| *product* | | The software product being developed; formally defined by the Requirements specification (folder '03_Requirements'). |
| *test case* | Declared with `TEST_DEF` (§1) | The smallest unit of the test suite: a function returning `bool`, which asserts one concrete expectation about *product* and yields whether that expectation held. |
| *test group* | Declared with `TEST_DEF` (§1) | A function returning `bool` that runs *test cases* or further *test groups* with `TEST`, and yields whether all of them held. |
| *test suite* | | The whole of *product*'s tests, rooted in the function `test()` of 'test/test.cpp' (§2). |

## 1. Framework

The test suite uses *neatest*, a header-only macro framework carried over from the predecessor of *product* (see '00_agents.md' § Predecessor). It is placed in 'test/neatest.h', with 'test/neatest.cpp' including the header so that the header is compiled on its own at least once.

*neatest* needs no library, no build-system integration beyond compiling the 'test' folder, and no dependency to pin.

### 1.1 Macros

| Macro | Expands to | Used in |
| --- | --- | --- |
| `TEST_INIT()` | the declaration of the local success flag | the first line of every *test group* and of every *test case* that asserts |
| `TEST_DEF( NAME )` | `bool TestNAME()` | the declaration and the definition of a *test case* or *test group* |
| `TEST( NAME )` | calls `TestNAME()`, prints its result, and prints file and line where it failed | inside a *test group* |
| `TEST_ASSERT( EXPRESSION )` | records failure, printing the expression, file and line, where `EXPRESSION` is false | inside a *test case* |
| `TEST_FRIEND( NAME )` | `friend bool TestNAME()` | inside a class declaration, to reach its private members (§5) |
| `TEST_RETURN()` | `return` of the success flag | the last line of every *test group* and of every asserting *test case* |
| `TEST_SUCCESS` | the success flag itself | where the flag is read rather than returned |

### 1.2 The assertion macro

`TEST_ASSERT` is the one addition this guideline makes to *neatest* as it was carried over. Without it a *test case* can only return `false`, which reports that the case failed but not which expectation broke; `TEST` prints the file and line of the call in the *test group*, not of the expectation itself.

'test/neatest.h' therefore declares:

```cpp
#define TEST_ASSERT( EXPRESSION )                                           \
    if ( ! ( EXPRESSION ) )                                                 \
    {                                                                       \
        _test_bSuccess = false;                                             \
        cout                                                                \
            << "   assertion failed: " #EXPRESSION "\n"                     \
            << "   file:" << __FILE__ << "\n"                               \
            << "   line:" << __LINE__ << "\n";                              \
    }
```

`TEST_ASSERT` does not return. Every assertion of a *test case* is therefore evaluated, and one run reports every expectation of that case that broke.

### 1.3 Order of execution

`TEST` runs a *test case* or *test group* only while the enclosing group has not failed: the first failure ends the remaining tests of that group. A *test group* therefore reports the first of its members that failed, not all of them.

This is a property of the framework, not an oversight. A *test case* is written so that it does not depend on a test that ran before it (§6, independence); where a group's later tests would nevertheless be worth running after a failure, the tests are split into separate groups called from the root (§2).

## 2. Test suite structure

The test suite has three levels.

| Level | File | Content |
| --- | --- | --- |
| Root | 'test/test.h', 'test/test.cpp' | `bool test()`, which runs one *test group* per component of the design ('02_02_design.md' § Architecture overview) |
| Group | 'test/test_<component>.h', 'test/test_<component>.cpp' | one *test group* per component, running the *test cases* of that component |
| Case | in the group's own '.cpp' | the *test cases* themselves |

The root runs every group:

```cpp
// test/test.cpp
#include "test.h"

#include "test_parser.h"

bool test()
{
    TEST_INIT();
    TEST( parser );
    TEST_RETURN();
}
```

A group declares itself in its header and defines itself in its source:

```cpp
// test/test_parser.h
#ifndef test_parser_h
#define test_parser_h

#include "neatest.h"

TEST_DEF( parser );

#endif // test_parser_h
```

```cpp
// test/test_parser.cpp
#include "test_parser.h"

#include "parser.h"

/********** forward declarations **************************************************************************************/

TEST_DEF( parserEmptyInput );
TEST_DEF( parserSingleWord );

/********** test group ************************************************************************************************/

TEST_DEF( parser )
{
    TEST_INIT();
    TEST( parserEmptyInput );
    TEST( parserSingleWord );
    TEST_RETURN();
}

/********** test cases ************************************************************************************************/

TEST_DEF( parserEmptyInput )
{
    TEST_INIT();
    TEST_ASSERT( genc3wb::parser::parse("").isEmpty() );
    TEST_RETURN();
}
```

Every *test case* is forward-declared above the *test group* that runs it, so that the group reads as the list of what it covers.

## 3. Naming

- A *test group* covering a component is named after that component's namespace, without the `genc3wb::` prefix and in lower camel case: component `genc3wb::parser` is covered by `TEST_DEF( parser )` in 'test/test_parser.h'.
- A *test case* is named by its group's name followed by what it asserts: `parserEmptyInput`, `parserSingleWord`. The group's name as prefix keeps the case names unique across the whole suite, which the macros require, since every `TEST_DEF` becomes a function of the same namespace.
- A *test case* covering a fault that was corrected is named after the fault, not after the correction.

## 4. Writing tests

- A *test case* asserts one concrete expectation with `TEST_ASSERT`. Where several assertions describe one expectation together — a returned value and the state it leaves behind — they belong in the same case; where they describe independent expectations, they belong in separate cases.
- A *test case* sets up whatever it needs itself and leaves no state behind for another case, so that the order in which cases run cannot change the result.
- An expectation about a *quality requirement* ('02_01_requirements.md' §4.1) that names a measurable bound is asserted against that bound, not against a value observed once on one machine.

## 5. Testing private members

A *test case* that must reach a private member declares itself a friend of the class under test, with `TEST_FRIEND` inside the class declaration:

```cpp
class Parser
{
    TEST_FRIEND( parserInternalState );
    // ...
};
```

The friend declaration names one *test case*, never a whole group, so that the class states exactly which test reaches into it. A member that several cases must reach is a sign that it belongs to the component's public interface ('02_02_design.md' § Function signatures) rather than to its private part.

## 6. Validation checklist

Before a function, a class, or a component is considered tested, the *test group* covering it carries a comment recording which of the following criteria are met, using `✅` (met), `❌` (not yet met), `❓` (unclear), or `N/A` (not applicable):

- **Function** — completeness (every equivalence class, or a representative sample, is covered), independence (from any other *test case*), edge cases (the boundaries of every parameter's range), and conformance to the function's documented contract ('02_04_coding.md' § Function declarations).
- **Class** — everything above for each of its public member functions, plus: every constructor is exercised, and the state the class leaves behind is asserted wherever it is observable.
- **Component** — everything above for each of its classes and free functions, plus: every requirement realised by the component ('02_02_design.md' § Traceability) is covered by at least one *test case*.

```cpp
/*  * validated        : ✅
    * completeness     : ✅
    * independence     : ✅
    * edge cases       : ✅
    * conforms to doc  : ✅ */
TEST_DEF( parser )
{
    // ...
}
```

## 7. Test run output

A test run stores its output as file './reports/test.txt'.

A test run reports its test coverage under './reports/'.
